Descripción pública original del libro

inglés

REVERSE ENGINEERING WITH REA is an evidence-centered guide to using AI-assisted tooling for authorized software investigation without confusing fluent explanations, decompiler output, or reconstructed code with proof. The book treats REA as evidence-access infrastructure that can connect an AI agent to bounded analysis operations, while keeping the analyst responsible for scope, authorization, interpretation, uncertainty and publication. It begins by distinguishing what REA can actually observe from what an agent merely infers, then establishes professional boundaries for lawful possession, inspection, runtime experimentation, evidence retention, independent implementation and public release. The recurring principle is simple: technical capability does not itself create permission, and a strong reverse-engineering conclusion must be traceable to authentic evidence rather than to a plausible narrative. The workstation and tooling chapters turn setup into part of the experiment. Instead of assuming that a successful installer means the analysis stack is ready, the book separates runtime compatibility, agent registration, provider readiness and a genuine evidence-producing response. It covers reproducible host records, package and provider versions, hashes, least-privilege working directories, read-only originals, REA CLI and MCP concepts, and the need to distinguish a workflow skill from a live analysis provider. The text emphasizes that failures and blocked capabilities belong in the research record: an unavailable provider, incompatible runtime or missing capture must be documented as an unavailable lane rather than replaced by invented output. The investigation methodology moves from question framing and artifact triage into native binaries, assembly, linking…

Objetivos de aprendizaje publicados

inglés

  • Distinguish evidence produced by an analysis tool from an AI agent's interpretation so that fluent output is never mistaken for proof.
  • Define authorization separately for inspection, execution, capture, retention, reconstruction and publication before beginning a reverse-engineering investigation.
  • Build a reproducible REA workstation by recording runtime, operating system, package, provider, permission and artifact versions rather than relying on the word latest.
  • Understand the difference between an agent workflow, MCP registration, provider readiness and a genuine evidence-producing analysis response.
  • Frame a reverse-engineering project around the smallest important behavioral question and select only the analysis capability needed to answer it.
  • Perform artifact triage and maintain hashes, read-only originals, evidence directories, manifests and a chain of custody for research inputs and outputs.
  • Read assembly, disassembly and decompiler output with explicit uncertainty, cross-checking recovered high-level expressions against lower-level evidence and boundary tests.
  • Treat decompiled pseudocode as a testable hypothesis rather than as recovered original source code.
